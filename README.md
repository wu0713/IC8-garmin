# 跑課 · Garmin-IC8

讀你的 Garmin 數據，每天自動重排接下來 7 天的跑步課表，同步到 iPhone 行事曆（也可以推回 Garmin 手錶）。
可以架在自己電腦上和朋友共用，每個人各自登入、各自連自己的 Garmin。

- **免費**：用 GitHub 開源的 [python-garminconnect](https://github.com/cyberjunky/python-garminconnect)，不用 Garmin 官方付費或企業 API
- **iPhone 不用付費開發者帳號**：做成 PWA，Safari「加入主畫面」就是一個 App
- **不制式化**：沒有寫死的課表模板，每個人自訂目標、可跑日、強度、喜歡的課

App 有四個分頁（今天／紀錄／課表／夥伴）。視覺是自己的「冒險手冊」風格：粗墨線、硬陰影、分格能量條，和像素角色同一個世界。功能規劃參考過 [Unified Health](https://github.com/NoatToan/unified_watch_health_connect)（指標趨勢、單趟詳情的資訊架構），版面與樣式為本專案自行設計。

| 分頁 | 內容 |
|---|---|
| **今天** | 「今日任務」卡（今天的課＋夥伴＋體力條）、三條進度條（本週跑步／活動熱量／步數）、手錶狀態列、**可自訂的指標儀表板**（勾選、排序、格狀／清單）。點任一指標可看週／月／6 個月／年趨勢、平均線與趨勢線 |
| **紀錄** | 本週跑量與近 13 週長條圖（虛線是前 4 週平均）、本月月曆（實際里程＋排好的課）、長期規劃、活動列表 → 單趟詳情（**訓練報告**、心率曲線、配速曲線、心率區間、每公里分段、當天課表對照） |
| **課表** | 課表可切換**本週／本月**（本月是月曆，8 天後為預估課表，點任一天都能自己改，最遠 60 天）、「計畫 vs 實際」與完成度、能力概況（找出最需要補足的面向）、本週建議、**直接調整課表**（改成別的課、跟另一天交換、改休息、恢復自動排課）、回報今天感覺、長期趨勢與建議 |
| **夥伴** | 跑步夥伴（12 種角色 × 5 個成長階段）、跑友排行、目標與課表偏好、健康參考範圍（心率區間、訓練配速）、行事曆訂閱、手錶與資料來源 |

```
Garmin 手錶 → Garmin Connect ──(python-garminconnect，每天 3 次)──┐
                                                                   ▼
                     你的電腦：FastAPI + SQLite（Docker 或直接跑 Python）
                     ├─ 計算 訓練負荷 / 體能 CTL / 疲勞 ATL / 狀態 TSB / 恢復分數
                     ├─ 排課引擎 → 未來 7 天課表
                     ├─ /cal/<私密token>.ics  → iPhone 行事曆訂閱（自動更新）
                     ├─ （選用）把課表推回 Garmin → 手錶照配速提示跑
                     └─ PWA 網頁 → iPhone 加入主畫面
                                                                   ▲
                     Tailscale Funnel（免費 https 網址）← 你和朋友的手機
```

## 1. 啟動（在你的電腦上）

> 想直接架好、讓手機和朋友從外面連？跳到第 2 節，用一鍵腳本就好。

### 方法 A：Docker（推薦）

```bash
cp .env.example .env        # 編輯 .env，至少把 INVITE_CODE 改掉
docker compose up -d --build
```

### 方法 B：直接用 Python 3.12+

```bash
cp .env.example .env
./run.sh                    # macOS / Linux
# Windows：PowerShell 執行 .\run.ps1
```

打開 <http://localhost:8000>，建立帳號，按「使用範例資料」可以先看效果；要用真的資料就按「連結 Garmin」。

> 資料全部在 `data/` 資料夾：SQLite 資料庫和加密金鑰 `secret.key`。換電腦時整個資料夾一起搬，並記得備份。

## 2. 架在家裡常開的電腦，用免費網址連進來（Tailscale Funnel）

[Tailscale Funnel](https://tailscale.com/kb/1223/funnel) 免費提供一個公開的 https 網址，例如 `https://ben-pi.tail1234.ts.net`，連線會轉進你家這台電腦。

- 路由器不用開 port
- 不用買網域
- 不用自己弄 SSL 憑證
- 朋友不用安裝任何東西

開始前，先申請一個免費的 [Tailscale](https://tailscale.com) 帳號，用 Google、GitHub 或 Microsoft 帳號登入就可以。

### Linux／樹莓派／Ubuntu（一鍵）

```bash
bash deploy/setup-linux.sh
```

腳本會自動完成：

1. 安裝 Docker 和 Tailscale
2. 產生邀請碼
3. 啟動 App
4. 開啟 Funnel
5. 把網址寫進 `.env`

最後會印出網址和邀請碼。腳本可以重複執行，已經做過的步驟會跳過。

- 第一次會跳出 Tailscale 登入網址，用瀏覽器打開並登入即可。
- 如果帳號還沒開通 Funnel，會再跳出一個網址，打開按同意後，腳本會自己繼續。
- 樹莓派請用 **64 位元** 的 Raspberry Pi OS。Pi 4／Pi 5 都夠用。

### Windows 10／11（一鍵）

在專案資料夾按右鍵「在終端機中開啟」，然後執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\setup-windows.ps1
```

腳本會自動完成：

1. 安裝 Python 和 Tailscale
2. 建立「開機自動啟動」排程（不用登入 Windows 也會跑）
3. 把插電時的睡眠關掉
4. 開啟 Funnel

注意：專案資料夾要放在本機硬碟，不要放在網路磁碟。

### Synology NAS

1. 在套件中心安裝 **Container Manager** 和 **Tailscale**，並登入 Tailscale。
2. 把專案資料夾放到 NAS（例如 `/volume1/docker/garmin-ic8`），把 `.env.example` 複製成 `.env`，並修改 `INVITE_CODE`。
3. Container Manager → 專案 → 新增 → 選這個資料夾，它會使用 `docker-compose.yml`，然後啟動。
4. SSH 登入 NAS，執行 `sudo tailscale funnel --bg 8000`，把印出的網址填進 `.env` 的 `PUBLIC_BASE_URL`，再到 Container Manager 重啟專案。

### 之後的維護

| 想做的事 | 指令 |
|---|---|
| Garmin 同步一直失敗（通常是 Garmin 改了登入方式） | `bash deploy/update.sh`（Windows：重新執行 setup 腳本） |
| 看執行紀錄 | `docker compose logs -f`（Windows：`data\server.log`） |
| 暫時關閉對外網址 | `tailscale funnel --bg 8000 off` |
| 備份 | 複製整個 `data/` 資料夾 |

> 安全性：
> - App 只監聽本機（`127.0.0.1`），外面只能從 Funnel 的 https 網址進來。
> - 要有邀請碼才能註冊。
> - 行事曆網址含有一組隨機 token，外流的話可以在設定裡換一組新的。

## 3. iPhone 上怎麼用

**安裝 App**
1. 用 Safari 打開你的網址。
2. 按分享 → **加入主畫面**。
3. 之後從主畫面的「跑課」圖示打開，就是全螢幕 App。

**同步到行事曆**
1. App 裡到「我的 → 放進 iPhone 行事曆」→ **訂閱行事曆**，iPhone 會跳出訂閱確認。
2. 沒反應的話，複製網址，到「設定 → App → 行事曆 → 行事曆帳號 → 加入帳號 → 其他 → 加入已訂閱的行事曆」貼上。
3. 課表變動時，行事曆會自動更新。可以在行事曆帳號設定把「抓取」改成每 15 分鐘或每小時。

**推到 Garmin 手錶（選用）**
到「我的 → 目標與課表偏好 → 其他」勾選「把課表推到 Garmin 手錶」。每次同步時，有變動的課會上傳到 Garmin Connect 行事曆，手錶同步後就能直接開課跑，有配速提示。
App 只會動到名稱以 `[IC8]` 開頭的課表，不會碰到你其他的課表。

## 4. 排課邏輯（可以自己改 `app/planner.py`）

每天同步後，或你在 App 裡回報感覺、改設定時，都會依最新資料重排「今天起 7 天」：

1. **訓練負荷**：每次跑步用 Banister TRIMP（心率儲備 × 時間）算負荷，再算出：
   - 體能 CTL：42 天平均
   - 疲勞 ATL：7 天平均
   - 狀態 TSB：CTL − ATL
2. **恢復分數 0–100**：綜合 TSB、HRV（和你自己的 5 週基準比）、睡眠分數、Body Battery、安靜心率（和基準比），以及你在分析頁回報的「今天感覺 1–5」。
3. **週跑量**：取近 4 週中跑量最高的 3 週平均，依「進步速度」增加 3% / 7% / 10%，每週最多 +45 分鐘。另外：
   - 每 N 週一個減量週（量 × 0.75）
   - 比賽前 2 週減量
   - 疲勞過高時自動降 15%
4. **分配到你能跑的日子**：
   - 長跑放在你指定的那天
   - 依強度滑桿決定每週 0–2 堂強度課，並盡量不排在長跑或彼此的隔天
   - 剩下的量平均給輕鬆跑；分不到 25 分鐘就改成休息
5. **選課**：只從你勾選喜歡的課裡挑，並避開最近做過的，避免一直重複。如果目標是比賽，會依離比賽的週數切換重點：
   - 打底期：坡道、法特雷克
   - 強化期：節奏跑、間歇、比賽配速
   - 巔峰期：比賽配速、間歇
   - 減量期：短而有力的課
6. **依今天狀態調整**：
   - 恢復分數 < 40：今天的強度課改成恢復跑，原本的課往後挪
   - 恢復分數 < 25：今天改休息
   - 恢復分數 40–65：間歇改成法特雷克、節奏跑改成漸進跑、長跑縮短 15%

配速會從你最近的跑步紀錄自動估算，也可以在設定裡自己填輕鬆配速和閾值配速。

## 4.3 新手期與其他貼心設計

- **新手期**：紀錄不到 3 週、或近 4 週少於 6 次跑步時，只排輕鬆跑（每次最短 20 分鐘）、不排強度課和長跑；恢復分數不計「近期疲勞」，也不顯示「加量幅度」，避免資料太少造成誤報。
- **跳過今天的課**：會記住被跳過的是哪一堂，並在課表頁提議挪到最近的休息日，一鍵完成。
- **課表內容**：在課表頁點課名，可以看熱身／主課／緩和的分段和建議配速。
- **大字模式**：夥伴頁最下面可以開啟，整個 App 放大 15%。
- **還沒連手錶**：可以先選夥伴、看排行，之後再連結。
- **連線檢查／測試推課表**：夥伴 → 手錶與資料來源。

## 4.4 自己排課、比賽、訓練報告

- **排課方式**（我的 → 目標與課表偏好）：
  - 自動排課：依資料與偏好自動排，每天依身體狀態微調。
  - 我自己安排：填一份每週課表（每天的課種和分鐘數），之後固定照它排；App 只給建議，不會自動改課。
  - 兩種方式下，都可以在分析頁的月曆點任一天單獨改課；手動改過的會保留。
- **比賽**：同一頁可以加入多場比賽。比賽當天顯示比賽；前 3 天不排強度課和長跑，前一天只排 20 分鐘恢復跑；賽後隔天休息，之後依距離安排 1–5 天恢復跑；當週跑量降 20%。
- **訓練報告**：每趟跑步都有一份，最多六個面向，各給「好／普通／要加強」和調整建議：
  - 完成度（實際 vs 計畫時間）
  - 強度控制／強度到位（輕鬆課是否夠輕鬆、強度課是否夠強）
  - 配速穩定度（每公里配速起伏）
  - 後半表現（有沒有掉速）
  - 心率飄移（同配速下後半心率升高多少，反映有氧耐力）
  - 步頻
  同步到今天的新跑步時，會直接跳到這份報告。

## 4.4.1 晨報、晚報與其他運動

- **晨報**（預設 07:30）：比較今天早上的安靜心率和昨天、前 7 天平均，加上昨晚 HRV、睡眠、Body Battery、近 7 天活動量，判斷今天「照課表／減量／休息」。需要調整時有一鍵套用按鈕。安靜心率高出平常 7 下以上是最重的訊號。
- 晨報會等抓到「今天的安靜心率」才推播（手錶要先同步到手機的 Garmin Connect），最多延後 3 小時。
- **晚報**（預設 21:30）：步數、活動熱量、壓力、目前電量、今天的運動與負荷、明天的課和今晚的睡眠建議。
- **手機通知**：用免費的網頁推播（Web Push）。iPhone 需要 iOS 16.4 以上、從 Safari「加入主畫面」後從圖示打開，而且要用 https 網址（Tailscale Funnel）。在「夥伴 → 晨報與晚報」開啟。
- **其他運動**：Garmin 上的騎車、游泳、重訓、瑜珈、球類等都會同步進「紀錄」。它們不算跑量和經驗值，但會算進總活動量、恢復分數和課表的疲勞判斷。「總活動量」卡片會把近 7 天總負荷和前 4 週平均比較：0.8–1.3 倍適中、1.3–1.5 偏多、超過 1.5 過多。

## 4.5 角色與經驗值

角色清單在 `web/characters/manifest.json`，圖片在 `web/characters/<角色>/<階段>.png`。**之後要新增或替換角色，只要換圖片、改 manifest，不用改程式。**

| 怎麼賺 | 經驗值 |
|---|---|
| 每跑 1 公里 | +10 |
| 在有排課的日子完成跑步 | +20 |
| 一週跑滿 3 次 | +50 |
| 破 PB（1K／1 英里／5K／10K／半馬／全馬／最長距離） | +80～+500 |
| 第一次完成 5K／10K／半馬／全馬 | +100～+400 |

- 升到第 L 級需要的累計經驗值是 `40 × L × (L−1)`。
- 每隻角色有 5 個階段，分別在 Lv 1、4、9、16、25 解鎖（manifest 的 `stage_levels`）。照每週約 25 公里來算，大約 1 個月第一次進化，1.5～2 年到最終型態。
- 經驗值從選角色那天開始算。之前的紀錄變成「孵化禮」：那些紀錄經驗值的 10%，最多 400。
- 換角色不會失去等級。
- 角色是動態的：會呼吸、偶爾小跳，點一下會跳起來；第 3 階段起身邊有閃光。系統開啟「減少動態效果」時會自動停用。
- 同一系列的 5 個階段用同一個縮放倍率顯示，所以畫面上會真的越長越大。
- 目前的角色圖是從角色總覽圖自動去背切出來的（`tools/extract_sheet.py`）。拿到原始透明 PNG 後，直接覆蓋同名檔案，並更新 manifest 裡的 `w`、`h` 即可。

## 5. 關於 Garmin 串接（請先了解）

- python-garminconnect 是**非官方**套件，模擬官方 Garmin Connect App 的登入方式。Garmin 改版時可能會暫時失效（2026 年 3 月就發生過一次，套件作者幾天內就修好了）。
  - **出問題時**：先升級套件。Docker 用 `docker compose build --no-cache && docker compose up -d`；Python 用 `pip install -U garminconnect`。
  - 摘要頁最上面會顯示「上次同步失敗」和錯誤原因。
- **Garmin 密碼不會被儲存**：只在連結的那一次用來換取登入憑證，憑證以 Fernet 加密後存進資料庫。
- **有開兩步驟驗證（MFA）也可以**：連結時 App 會請你輸入驗證碼。
- 這種用法屬於個人自用；Garmin 的服務條款並沒有明確允許這樣存取。請自行評估，也不要用太高的頻率同步。預設一天 3 次。

## 6. 開發

```bash
pip install -r requirements-dev.txt
pytest -q                      # 54 個測試：排課、API、多使用者隔離、行事曆、Garmin 課表、分析建議、長期規劃、經驗值、新版各頁 API、資料庫遷移
uvicorn app.main:app --reload
```

```
app/
  main.py          API、行事曆訂閱、靜態檔、每日排程
  garmin_client.py Garmin 串接（真實 / Demo 假資料）
  sync.py          同步流程
  metrics.py       TRIMP、CTL/ATL/TSB、恢復分數、配速估算
  planner.py       排課引擎（想改規則就改這裡）
  garmin_push.py   課表推回 Garmin 手錶
  ics.py           iCalendar 產生
  analysis.py      跑步分析與建議規則
  season.py        長期週期規劃、月曆
  game.py          角色、經驗值、等級、排行榜
  views.py         摘要、指標趨勢、活動詳情、本週課表、健康參考範圍
web/               PWA（純 HTML/CSS/JS，不用建置）：js/ 每頁一個檔案、characters/ 角色圖
deploy/            一鍵架站腳本（Linux／Windows）與升級腳本
tools/extract_sheet.py  從角色總覽圖切圖去背的工具
tests/
```

**使用的開源專案**
- [python-garminconnect](https://github.com/cyberjunky/python-garminconnect)（MIT）
- FastAPI、icalendar、APScheduler、cryptography
- CTL/ATL/TSB 模型概念來自開源專案 [GoldenCheetah](https://github.com/GoldenCheetah/GoldenCheetah) 的 Performance Manager Chart
